# resume-jd-tailor — 简历 JD 适配

> 核心信念：**简历不是履历复述，是匹配度论证。** 目标是让 HR 30 秒内看到"这个人能干这活"，并让 ATS 关键词命中。
> 铁律：**可以重新框定、提炼、突出，绝不虚构经历。** 诚实口径的上限写满，比夸大后面试崩掉好。

## 一、先诊断，再动手

拿到简历先做 8 项体检，逐项写结论（不要闷头改）：

| 检查项 | 常见病 |
|---|---|
| 求职意向 | 与目标岗位零关键词关联，ATS 直接过滤 |
| 技术资产埋没 | 技能只在"技能标签墙"里，正文经历完全不体现 |
| 职责 vs 成果 | 写"负责了什么"而非"做成了什么"；量化数据堆在大段文字末尾被跳过 |
| 经历重复 | "项目经历"整段复制"工作经历"，浪费版面稀释信息 |
| 冗余弱相关 | 与岗位无关的证书/技能占据显眼位置 |
| 证书重复罗列 | 同一证书出现 2 次以上 |
| 自我评价抒情 | 600 字主观自述，无可验证能力信号，HR 平均阅读不足 30 秒 |
| 口径矛盾 | 学历/年限在不同版本间不一致 → 背调风险 |

## 二、对照 JD 逐段映射

把 JD 要求拆成一行一行的表格，三列：**岗位要求 → 原简历状态 → 优化动作**。

```markdown
| 岗位要求（JD 原文/市场通用基准） | 原简历状态 | 优化动作 |
|---|---|---|
| Python 编程 | 仅在技能标签写"良好" | 提至个人优势 + 技能区首行，与数据/DB 组合成能力组 |
| Prompt 工程 / RAG / AI Agent | 完全未出现 | 新增技能组，按"熟悉范式 + 关注场景"的诚实口径撰写 |
```

**没有 JD 原文时**：以目标岗位的市场公开招聘通用要求为基准，并在输出开头声明"未提供 JD 原文，以市场通用基准优化"。

## 三、成果表达强化（核心手法）

改写公式：**动词 + 内容 + 量化结果**。把"职责句"改成"成果句"。

| 改写前 | 改写后 |
|---|---|
| 负责项目申报材料的全周期管理 | 主导技术方案设计与申报材料编制，组织合规性自查并跟进审批进度，单年最高通过国家级高新技术企业认定 **24 家**、单年通过项目 **60+** |
| 建立项目信息数据库，采集执行数据 | 搭建项目信息数据库（业务知识库雏形），输出《项目监测报告》，为方案迭代与管理决策提供数据支撑 |
| 一周内完成了从签单到申报的高企认定 | 提升为独立量化亮点：曾 **1 周内** 完成从签单到申报的高新技术企业认定交付 |

**让旧经历与新岗位产生联想**：加一个括号类比（如"业务知识库雏形"），把申报咨询的经验翻译成目标岗位的语言（RAG 知识库）。这是重新框定，不是编造。

## 四、结构与删减

- **顺序重排**：个人优势（含岗位关键词）→ 专业技能（按岗位优先级分组）→ 工作经历 → 代表性项目 → 教育 → 证书
- **工作经历改 bullet**：每条「动词 + 内容 + 量化结果」，不要大纲式"一、二、三"
- **项目经历去重**：不复制工作描述，改为按类型罗列清单
- **删**：无关证书/设计类软件标签/重复证书/抒情自述
- **保留但如实**：不夸语言能力、不夸熟练度

## 五、诚实口径检查（交付前必做）

输出必须包含这段提醒：

1. **哪些经历没有可佐证的项目？** 按"熟悉范式"口径写是安全上限；若面试深问，建议补 1–2 个可演示的实践项目。
2. **学历/专业是否匹配目标岗位的硬性要求？** 部分大厂岗要求硕士，投递时优先选"应用层/业务落地型"而非"算法研发型"。
3. **建议准备 2 个面试故事**：从真实经历里挑最有张力的（如极限交付、数据驱动决策），能自然延伸到目标岗位的能力模型。

## 六、匹配度评估

改前改后各给一次关键词重合度估算（如 10%–15% → 60%–70%），并说明**仍缺什么**。不要只说"优化得很好"。

## 七、输出要求

- 逐项诊断结论（8 项体检表）
- 对照 JD 的映射表
- 改写前后对比示例（至少 4 条）
- 结构与删减清单
- 诚实口径提醒
- 匹配度评估（改前/改后 + 仍缺项）
